# Gotchas

## JWT

- **`exp` is seconds.** `Date.now()` is milliseconds. A token signed with `exp: Date.now() + 3600` is valid for 55,000 years.
- **ECDSA in JWS is raw `r‖s`, not DER.** WebCrypto returns raw; Node's `crypto.sign` returns DER unless `dsaEncoding: 'ieee-p1363'` is passed. Interop tests must set it.
- **`jsrsasign` treats a hex-looking string as hex.** Measured on 1.0.3 with both 8.0.24 and 11.1.5: the secret `deadbeef` signs with bytes `de ad be ef`, not the UTF-8 text, so the token fails verification everywhere else. Any 1.0.x caller with such a secret has tokens 2.0.0 will reject unless they pass `hexToBytes(secret)` — the migration guide must say so.
- **`decode` in 1.0.x verified, and returned `jsrsasign`'s parse object** (`headerObj`, `payloadObj`, `sigHex`, …), not the payload the README implied. A 2.0.0 function named `decode` that did not verify would silently remove a security check from every upgraded caller.

## Hermes / React Native

- **No WebCrypto.** `globalThis.crypto.subtle` is undefined; `crypto.getRandomValues` too, unless the host installs `react-native-get-random-values`. Signing with HMAC, ECDSA, Ed25519, and RSA PKCS#1 v1.5 needs no randomness; RSA-PSS signing (random salt) and key generation do. RSA signing of either kind uses it for blinding when it is there ([../domain/keys.md](../domain/keys.md#rsa-blinding)). noble 2.x ECDSA is deterministic only because `extraEntropy` defaults to `false` — passing `true` would make every ES* signature need the RNG.
- **`atob`/`btoa` exist only from React Native 0.74**, and work on Latin-1 strings. The library carries its own base64url over bytes.
- **`TextEncoder` exists in Hermes only from React Native 0.74** (Hermes' sources: `lib/VM/JSLib/TextEncoder.cpp` is absent at the 0.71, 0.72 and 0.73 tags, present at 0.74). `TextDecoder` is absent even in 0.87. The library's own code uses neither; noble needs `TextEncoder` at load — see the next point.
- **What Hermes in React Native 0.87.1 has**, measured on 2026-10-15 in a Release build on an iOS 18.3 simulator: `BigInt`, `Object.hasOwn`, `TextEncoder`, `atob` — yes; `TextDecoder`, `crypto.getRandomValues` — no. Older versions are what FT-001 stage 1a measures.
- **`jsrsasign` is slow on Hermes**, measured in the same run with 1.0.4: RS256 sign 1405 ms, ES256 verify 1746 ms, RS256 verify 43 ms, HS256 4 ms — each one call, blocking the JS thread. This is the 1.0.x baseline the noble backend must beat in stage 1a, and a reason in itself to leave `jsrsasign`.
- **Which Hermes has what**, read from Hermes' sources at the React Native release tags: `Object.hasOwn` is present at the RN 0.69 tag already; `BigInt` arrives at the RN 0.70 tag.
- **React Native 0.70 is excluded by its Babel preset, not by Hermes.** `metro-react-native-babel-preset` 0.72 (the RN 0.70 template's) includes `@babel/plugin-transform-exponentiation-operator`, which rewrites `a ** b` into `Math.pow(a, b)`. Metro applies the app's preset to `node_modules` too, so `c.Fn.ORDER ** _4n` in `@noble/curves/abstract/curve.js` (reached by Ed25519 scalar multiplication) throws `Cannot convert a BigInt value to a number`: Ed25519 signing throws a raw TypeError and verification turns into a silent `false`. Preset 0.73 (RN 0.71) dropped the plugin. Measured in the Hermes v0.12.0 CLI with each preset; `hostCheck` evaluates `BigInt(2) ** BigInt(3)` at import, through the same Babel setup, and names the cause. Any `@babel/preset-env` targeting engines without `**` does the same.
- **noble calls `TextEncoder` while its modules load, and only Metro shows it.** `ed25519.js`, `nist.js` and `secp256k1.js` call `createFROST(...)` at the top level; it encodes context strings with `utf8ToBytes`, i.e. `new TextEncoder()`. The calls are `/* @__PURE__ */`: esbuild and Rollup drop them when unused, Metro — which does not tree-shake — runs them. Without `TextEncoder`, importing the library throws `ReferenceError: TextEncoder is not defined`, HS256 included. This is why the floor is React Native 0.74 ([ADR-007](../adr/ADR-007-host-requirements-text-encoder.md)), and why the first floor measurement (0.71, in the Hermes v0.12 CLI with an esbuild bundle) was wrong: **measure host requirements through Metro**, or with tree-shaking off. `host.test.ts` fails if noble ever stops needing it.
- **BigInt is supported by Hermes** (React Native ≥ 0.70); all crypto except HS256 depends on it. The dependencies write `BigInt(0)`, not `0n` (checked by tokenizing every file on 2026-10-16), so a missing `BigInt` is a runtime error at load that `hostCheck` names — not a parse error.
- **noble calls `Object.hasOwn` while its modules load** — measured: with it deleted, importing `@noble/hashes/sha2.js`, any curve, or `micro-rsa-dsa-dh/rsa.js` throws `Object.hasOwn is not a function`. A check at the first `sign`/`verify` would be too late, so `src/host/hostCheck.ts` runs as the first import of `src/index.ts` ([ADR-007](../adr/ADR-007-host-requirements-text-encoder.md)). When Hermes gained it is undocumented; measure it, do not assume it.
- **Hermes for React Native 0.74 cannot parse `class`.** `class A {}` is a compile error (`invalid statement encountered`); there is no flag to allow it. `src/errors/errors.ts`, `src/keys/der.ts` and noble use classes, and run only because `@react-native/babel-preset` always lowers them (`new.target` is left as is, and Hermes has it, so `instanceof` on the error classes holds). A toolchain that bypasses the preset — SWC or esbuild targeting Hermes 0.74 directly — fails while parsing, before `hostCheck` can say why. Measured in the Hermes CLI for RN 0.74.1 (third review of 2026-10-17).
- **The RN preset's object spread is `Object.assign`.** `@react-native/babel-preset` 0.74 compiles `{ ...x }` with loose object-rest-spread, which calls the `__proto__` setter: an own `__proto__` key in `x` (as `JSON.parse` creates one) becomes the copy's prototype instead of a property. `sign` copied the payload so, and `iat`/`iss` were inherited from such a key; it copies own keys one by one now. Native spread, in Node and in `lib/`, defines a property.
- **BigInt `**` also runs while `ed25519.js` loads**, not only on the Ed25519 path: the module builds x25519 at the top level, and `montgomery()` computes `_2n ** BigInt(254)`. With a `**`-rewriting Babel setup the import itself would throw a TypeError; `hostCheck` catches it first.
- **Under Metro, noble loads lazily.** `@react-native/metro-config` turns on `inlineRequires` by default (0.74 and 0.87), so `src/index.ts`'s re-exports become getters and only `hostCheck`, `errors` and `legacy` run at import; the curve modules load on first use. Without `hostCheck` a missing `TextEncoder` would therefore surface at the first ES*/EdDSA import or call — and `curves.ts` turns some noble failures into "invalid key" — instead of at startup. `hostCheck` makes the failure immediate whatever the Metro config. Measured on a Metro bundle of `example/`, 2026-10-16.
- **noble probes `crypto.getRandomValues` once, when a curve module loads**, and without it switches off scalar-multiplication blinding for the life of the module. Signatures stay correct. Hence the README's rule: import `react-native-get-random-values` *before* this library, not merely before the first PS* call.
- **Metro's release build renames classes.** Terser mangles class names inside a module factory, so `this.name = new.target.name` made every error's `name` `"u"` in a release build (`instanceof` and `code` kept working; logs and crash reports did not). Error names are string literals on the prototypes now (`errors.ts`), and the device self-test checks `name` in a release build. Jest cannot see this: it does not minify.
- **`-{3,}` before a literal is quadratic.** `PEM_ARMOR = /-{3,}[ \t]*BEGIN…/` scanned 64 KB of dashes in 7 seconds: at every start position the run is consumed and then given back. `-{3}` matches the same armor lines in linear time. Patterns in `keyMaterial.ts` run on every `sign` and `verify` with a secret, so each must stay linear; the review3 test times one.
- **noble 2.x rejects high-S ECDSA signatures by default** (`lowS: true` for every curve, not only secp256k1). OpenSSL — Node, and most servers — produces high-S signatures about half the time, so ES* tokens from a server would fail verification at random. `verifyBytes` passes `lowS: false`; the interop suite verifies twenty Node signatures per curve to keep it that way.

- **Expo Go keeps a production bundle by URL.** With `expo start --no-dev --minify`, reopening the same `exp://host:port` in Expo Go showed the previous bundle even after `--clear` — Metro logged no new "Bundled" line — and `CI=1` turns reloads off as well. Mark each variant visibly (a title) and use a new port, or run in development mode, which Expo Go does not keep. On the Realme RMX3363, `pm clear host.exp.exponent` over adb is refused. Seen on 2026-10-16 with Expo Go 58.0.4.

- **A barrel's side-effect import dies with the barrel.** With `sideEffects` naming only `host/hostCheck`, webpack 5 (production) and Rollup skipped `index.js` for its re-exports and the host check never ran: a missing `Object.hasOwn` surfaced as a raw TypeError. Listing the entry points in `sideEffects` fixed both; esbuild kept the check either way. Found by the consumer-side review of 2026-10-17.
- **react-native-get-random-values in Expo Go uses `expo-crypto`.** Expo provides no `crypto.getRandomValues` (measured: without a polyfill PS* fails in Expo Go), and the package is not in `expo/bundledNativeModules.json`; it works because its 2.x falls back to `global.expo.modules.ExpoCrypto` when its own native module is absent.

## Toolchain

- **A Release build of `example/` on Android can ship a stale bundle.** Gradle's `createBundleReleaseJsAndAssets` tracks files under `example/` only; when only the library's `../src` changed, it reports `UP-TO-DATE` and the APK carries the previous JavaScript. Measured on 2026-10-16: a self-test "passed" on code from before the change. Delete `example/android/app/build/generated/assets/react` before the build, and confirm with `strings index.android.bundle | grep <a new message>`. Xcode's bundle phase runs on every build.

- **`example/` runs the library from the folder above it, so Babel's helpers do not resolve.** Metro compiles `../src` and rewrites it to import `@babel/runtime/helpers/…`; resolution starts next to the library's files, finds the root's `node_modules` without `@babel/runtime`, and fails the bundle. `example/metro.config.js` maps `@babel/runtime` to the app's copy. A consumer installing from npm never hits this — the package sits inside the app's `node_modules`.

- **Objects from another realm are still plain objects.** Jest runs tests in a VM context, and Node's `KeyObject.export({ format: 'jwk' })` returns objects whose `Object.prototype` is not the test realm's. A plain-object check that compares with `Object.prototype` rejects them; `isPlainObject` checks that the prototype's prototype is null instead.

- **The React Native 0.87.1 template app crashes at launch on iOS 27 simulators** with `EXC_BREAKPOINT` in `_UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`: iOS 27 enforces the UIScene lifecycle the template does not declare. It dies before any JavaScript runs, so it says nothing about this library. Use an iOS 26 or older simulator, or adopt scenes in `example/`.
- **Release builds redact `console.log` in the unified log** (`<private>`), so a self-test screen is read from a screenshot, not from `log stream`.

- **No `files` field publishes the whole directory.** 1.0.3 had neither `files` nor `.npmignore`; with the memory bank added, `npm pack --dry-run` listed 52 files, 45 of them `memory_bank/`. 1.0.4 adds `files`. Run `npm pack --dry-run` before every publish.
- **`@noble/hashes`, `@noble/curves` 2.x and `micro-rsa-dsa-dh` are ESM-only** (`"type": "module"`, sub-paths end in `.js`). Metro handles that; Jest needs them in `transformIgnorePatterns` exceptions, and the CommonJS build `require()`s them — which works on Node ≥ 20.19 (`require(esm)`), the floor noble itself declares. `scripts/check-build.cjs` proves it on every `prepack`.
- **`micro-rsa-dsa-dh` accepts weak imported RSA keys.** Its own `keygen` enforces 2048 bits, imported keys get no check, by design. The 2048-bit floor is ours to enforce at import.
- **…and refuses large ones only when it is used.** Every operation throws for `n ≥ 2^16384` or `e ≥ 2^256`; `verifyBytes` turns that into `false`, so such a key would import fine and then report every token as "invalid signature". The import check mirrors both limits.
- **`@types/node` types `saltLength` of an `rsa-pss` key pair as a string.** Node takes a number of bytes; the tests cast.
- **Metro does not tree-shake, but it bundles per file.** Importing `@noble/curves` from its root would bundle every curve; import the exact sub-path.
